# LibraCore v1.1.7 — Reliability & Release Hardening

## Highlights

- Advances the backend and frontend release line to `1.1.7`.
- Carries forward the safe observability and database-aware readiness model from v1.1.6.
- Makes release validation explicitly verify synchronized backend, frontend, and lockfile metadata.
- Strengthens the release handoff around reproducible validation, artifact integrity, and rollback evidence.
- Keeps operational endpoints restricted to `health` and `info`.
- Keeps health details hidden and environment/Git metadata disabled.

## Reliability Focus

v1.1.7 is a release-hardening maintenance line. It does not intentionally change the public application API. The objective is to make the existing production behavior easier to validate and safer to promote between environments.

## Release Integrity

The release process must verify:

- backend version `1.1.7`;
- frontend version `1.1.7`;
- frontend lockfile root version `1.1.7`;
- exact tag-to-commit correspondence;
- successful release-blocking CI;
- packaged backend startup and health behavior;
- packaged readiness behavior with database dependency checks;
- safe `/actuator/info` build metadata;
- artifact integrity and SHA-256 checksums;
- absence of tracked secrets.

## Operations

The release retains the v1.1.6 operational model:

- liveness remains application-state based;
- readiness remains database-aware;
- Actuator exposure remains limited to `health,info`;
- health details remain hidden;
- environment metadata remains disabled;
- Git metadata remains disabled;
- performance-fixture writes remain explicitly gated and isolated from production databases.

## Upgrade Notes

Upgrade from v1.1.6 using the exact published `v1.1.7` artifacts. Validate startup, readiness, application smoke journeys, and the expected build metadata before production promotion.

## Rollback

If v1.1.7 fails deployment validation, roll back to the previously validated v1.1.6 release. Preserve the v1.1.7 tag and CI evidence; do not rewrite published history.

## Compatibility

v1.1.7 is intended to remain backward compatible within the LibraCore 1.1.x release line. No intentional breaking API change is introduced.

## Release Sequence

`v1.0.0 → v1.1.0 → v1.1.1 → v1.1.2 → v1.1.3 → v1.1.4 → v1.1.5 → v1.1.6 → v1.1.7`
