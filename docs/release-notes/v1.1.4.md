# LibraCore v1.1.4

## Release status

v1.1.4 is the next maintenance release after the v1.1.3 release candidate line. It is intended to ship only after the complete release validation pipeline is green.

## Highlights

- Advances the backend and frontend manifests to `1.1.4`.
- Keeps the committed frontend lockfile synchronized with the application manifest.
- Hardens the packaged-backend health gate with a longer startup retry window.
- Makes the release workflow select release notes from the Git tag instead of a stale hard-coded version.
- Preserves the established release sequence: `v1.0.0 → v1.1.0 → v1.1.1 → v1.1.2 → v1.1.3 → v1.1.4`.

## Verification gates

Before publishing `v1.1.4`, verify all of the following:

1. `node scripts/check-version.mjs 1.1.4` passes.
2. `frontend/package-lock.json` has root and package-root version `1.1.4`.
3. Backend Maven verification passes with PostgreSQL.
4. The packaged backend reaches `/actuator/health` within the extended retry window.
5. Frontend `npm ci` and `npm run check` pass.
6. CodeQL, backend CI, frontend CI, dependency review, version sync, and recovery-drill gates are green for the final release source.
7. The release workflow publishes the three expected artifacts and `SHA256SUMS.txt`.
8. Previous stable tags and releases remain unchanged.

## Upgrade from v1.1.2 / v1.1.3

This is a maintenance release. Existing database migrations remain authoritative; deploy the backend and frontend artifacts together and keep the existing environment variables and database configuration unless a deployment-specific change is required.

## Rollback

If deployment validation fails, stop the new application processes and restore the previous verified `v1.1.x` artifacts. Do not delete or rewrite existing Git tags.
