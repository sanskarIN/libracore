# LibraCore v1.1.1

LibraCore v1.1.1 is the next stable release line after v1.0.0, following the repository's corrected version sequence. The release focuses on release-source consistency, reproducible frontend dependency metadata, and stronger publication safeguards around the existing library-management platform.

## Highlights

- Advances the backend Maven version to `1.1.1`.
- Advances the frontend npm package version to `1.1.1`.
- Synchronizes the generated frontend lockfile with the release version.
- Extends the release-version guard to validate the frontend lockfile root metadata as well as the executable manifests.
- Keeps the tagged release workflow fail-closed before artifact publication.
- Preserves the existing `v1.0.0` and `v1.1.0` history without rewriting published tags.
- Retains the existing catalog, circulation, members, branches, reservations, fines, reporting, audit, notification, security, backup/restore, and responsive web application capabilities.

## Verification gates

The release must be published only from a tag whose source passes the complete release workflow:

1. backend Maven verification on Java 25;
2. PostgreSQL-backed packaged backend startup and `/actuator/health` verification;
3. frontend `npm ci` from the committed lockfile;
4. frontend lint, strict type checking, tests, and production build;
5. release-version and lockfile consistency validation;
6. packaged backend and frontend release artifacts;
7. SHA-256 checksum generation;
8. current security and dependency checks;
9. current Recovery Drill evidence where required by the repository release checklist.

## Upgrade notes

- Existing deployments should follow the normal database migration and backup procedure documented in `docs/release.md`.
- The release does not intentionally introduce a dependency upgrade; the frontend lockfile is synchronized as generated metadata.
- Do not roll back a deployed application binary across incompatible database migrations without a tested recovery/rollback plan.
