# LibraCore v1.1.9 — Release Automation, Testability & Maintenance

LibraCore v1.1.9 is a maintenance release focused on release automation, reproducible verification, clearer CI diagnostics, and continued operational consistency across the 1.1.x line.

## Highlights

- Advances the backend release line to `1.1.9`.
- Advances the frontend release line to `1.1.9`.
- Keeps the committed frontend lockfile synchronized with the executable frontend manifest.
- Continues deterministic release-readiness validation.
- Improves the repository's ability to diagnose failed release gates without weakening them.
- Preserves the liveness, database-aware readiness, restricted Actuator surface, performance-fixture isolation, and rollback model established in previous releases.

## Release Integrity

The v1.1.9 release contract requires backend, frontend, and lockfile versions to agree before publication. Repository-managed release documentation must also identify the same release version.

Release publication remains dependent on the complete release-blocking CI suite and tag-scoped validation.

## Operational Invariants

- Actuator exposure remains limited to `health` and `info`.
- Health details remain hidden.
- Environment metadata remains disabled.
- Git metadata remains disabled.
- Liveness remains application-state based.
- Readiness remains database-aware.
- Performance-fixture writes remain explicitly gated.
- Production databases must not be used by benchmark fixtures.
- Published tags must never be force-moved or rewritten.

## Verification Gates

Before publication, verify:

- backend version is `1.1.9`;
- frontend version is `1.1.9`;
- frontend lockfile root version is `1.1.9`;
- release documentation identifies `v1.1.9`;
- release-manifest validation passes;
- version guard passes;
- Backend CI passes;
- Frontend CI passes;
- Version Sync passes;
- CodeQL passes;
- dependency/security checks pass;
- Recovery Drill passes;
- Performance Fixture CI passes;
- Performance Thresholds CI passes;
- packaged startup, liveness, readiness, and build metadata checks pass;
- browser smoke and accessibility checks pass;
- deployment configuration and tracked-secret review pass;
- artifact and SHA-256 checksum review passes;
- the final `v1.1.9` tag points to the exact verified commit.

## Upgrade Notes

Users upgrading from `v1.1.8` should deploy the exact published `v1.1.9` artifacts and validate startup, database connectivity, readiness, liveness, build metadata, application smoke journeys, and deployment configuration.

No intentional breaking application API change is introduced.

## Rollback

If v1.1.9 fails deployment validation, roll back to the previously validated `v1.1.8` release. Preserve published history and never force-move the release tag.

## Compatibility

v1.1.9 is intended to remain backward compatible within the LibraCore 1.1.x release line.

## Release Sequence

`v1.0.0 → v1.1.0 → v1.1.1 → v1.1.2 → v1.1.3 → v1.1.4 → v1.1.5 → v1.1.6 → v1.1.7 → v1.1.8 → v1.1.9`
