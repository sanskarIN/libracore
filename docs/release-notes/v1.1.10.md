# LibraCore v1.1.10 — Verification, Reproducibility & Release Readiness

LibraCore v1.1.10 is a maintenance release focused on making the 1.1.x release process more deterministic, reproducible, and auditable while preserving the production-safety guarantees established by earlier releases.

## Highlights

- Advances the backend release line to `1.1.10`.
- Advances the frontend release line to `1.1.10`.
- Keeps the committed frontend lockfile synchronized with the executable frontend manifest.
- Updates the release-manifest audit workflow to use `1.1.10` as its default manual-audit version.
- Continues deterministic release-readiness validation.
- Preserves operational safeguards and the established rollback model.

## Release Integrity

The v1.1.10 release contract requires the backend, frontend, and frontend lockfile root versions to agree. Repository-managed release documentation must identify the same release version before publication.

Release publication remains dependent on the complete release-blocking CI suite, packaged verification, security checks, artifact integrity review, and tag-scoped validation.

## Operational Invariants

- Actuator exposure remains limited to `health` and `info`.
- Health details remain hidden.
- Environment metadata remains disabled.
- Git metadata remains disabled.
- Liveness remains application-state based.
- Readiness remains database-aware.
- Performance-fixture writes remain explicitly gated.
- Production databases must not be used by benchmark fixtures.
- Published tags must never be force-moved or rewritten.

## Verification Gates

Before publication, verify:

- backend version is `1.1.10`;
- frontend version is `1.1.10`;
- frontend lockfile root version is `1.1.10`;
- release documentation identifies `v1.1.10`;
- release-manifest validation passes;
- repository version guard passes;
- Backend CI passes;
- Frontend CI passes;
- Version Sync passes;
- CodeQL passes;
- dependency/security checks pass;
- Recovery Drill passes;
- Performance Fixture CI passes;
- Performance Thresholds CI passes;
- packaged startup, liveness, readiness, and build metadata checks pass;
- browser smoke and accessibility checks pass;
- deployment configuration and tracked-secret review pass;
- artifact and SHA-256 checksum review passes;
- the final `v1.1.10` tag points to the exact verified commit.

## Upgrade Notes

Users upgrading from the preceding validated 1.1.x release should deploy the exact published `v1.1.10` artifacts and validate startup, database connectivity, readiness, liveness, build metadata, application smoke journeys, and deployment configuration.

No intentional breaking application API change is introduced.

## Rollback

If v1.1.10 fails deployment validation, roll back to the previously validated stable release. Preserve published history and never force-move the release tag.

## Compatibility

v1.1.10 is intended to remain backward compatible within the LibraCore 1.1.x release line.

## Release Sequence

`v1.0.0 → v1.1.0 → v1.1.1 → v1.1.2 → v1.1.3 → v1.1.4 → v1.1.5 → v1.1.6 → v1.1.7 → v1.1.8 → v1.1.9 → v1.1.10`
