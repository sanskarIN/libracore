# LibraCore v1.1.8 — Release Integrity & Developer Experience

LibraCore v1.1.8 is a maintenance release focused on making version alignment, release validation, and contributor feedback more deterministic.

## Highlights

- Advances the backend release line to `1.1.8`.
- Advances the frontend release line to `1.1.8`.
- Keeps the committed frontend lockfile synchronized with the executable frontend manifest.
- Adds a dedicated release-manifest audit workflow.
- Makes version and release-document drift easier to detect before publication.
- Preserves the liveness, database-aware readiness, Actuator, performance-fixture, and deployment safeguards from previous releases.

## Release Integrity

The release-manifest audit verifies that the repository's backend version, frontend version, and frontend lockfile root version agree before a release is promoted.

The audit also verifies that the release notes for the requested release exist, reducing the chance of publishing a tag without repository-managed release documentation.

## Operational Invariants

- Actuator exposure remains limited to `health` and `info`.
- Health details remain hidden.
- Environment metadata remains disabled.
- Git metadata remains disabled.
- Liveness remains application-state based.
- Readiness remains database-aware.
- Performance-fixture writes remain explicitly gated.
- Production databases must not be used by benchmark fixtures.

## Verification Gates

Before publication, verify:

- backend version is `1.1.8`;
- frontend version is `1.1.8`;
- frontend lockfile root version is `1.1.8`;
- release-manifest audit passes;
- complete release-blocking CI passes;
- CodeQL and dependency/security checks pass;
- packaged startup, liveness, readiness, and build metadata checks pass;
- browser smoke and accessibility checks pass;
- deployment configuration and tracked-secret review pass;
- artifact and SHA-256 checksum review passes;
- the final `v1.1.8` tag points to the exact verified commit.

## Upgrade Notes

Users upgrading from `v1.1.7` should deploy the exact published `v1.1.8` artifacts and validate startup, database connectivity, readiness, liveness, build metadata, application smoke journeys, and deployment configuration.

No intentional breaking application API change is introduced.

## Rollback

If v1.1.8 fails deployment validation, roll back to the previously validated `v1.1.7` release. Preserve published history and never force-move the release tag.

## Compatibility

v1.1.8 is intended to remain backward compatible within the LibraCore 1.1.x release line.

## Release Sequence

`v1.0.0 → v1.1.0 → v1.1.1 → v1.1.2 → v1.1.3 → v1.1.4 → v1.1.5 → v1.1.6 → v1.1.7 → v1.1.8`
