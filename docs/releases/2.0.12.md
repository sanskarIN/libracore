# LibraCore 2.0.12 Release Candidate

**Prepared:** 2026-08-19  
**Target tag:** `v2.0.12`  
**Status:** source prepared; do not publish/tag until all release gates are closed.

## Version identity

- Backend Maven version: `2.0.12`
- Frontend npm version: `2.0.12`
- Frontend Settings version: injected from `frontend/package.json` at build time
- Version guard: `node scripts/check-version.mjs 2.0.12`

## Product scope

2.0.12 contains the completed LibraCore library-management implementation across cataloging, physical copies, members, accounts, role-based security, issue/return/renewal, reservations/waitlists, fines, circulation policy, reporting/audit, CSV exchange, notifications, staff-account administration, responsive web UI, themes, accessibility-oriented behavior, backup/restore tooling, CI/security automation, and project documentation.

## Release-hardening changes in 2.0.12

- synchronized backend/frontend executable versions;
- removed the hard-coded web version from Settings;
- added build-time frontend version injection;
- added a cross-manifest version validation script;
- added GitHub Actions version synchronization enforcement;
- made backend CI packaged-JAR startup independent of the Maven version filename;
- made release packaging independent of a historical backend JAR filename;
- made the release workflow verify tag/manifest version agreement;
- made the release workflow require `frontend/package-lock.json` and `npm ci`;
- made normal frontend CI read-only and lockfile-based;
- added an explicit maintainer-only Frontend Lockfile Bootstrap workflow.

## Required verification before tagging

The following must be completed against the exact intended release commit:

- [ ] `frontend/package-lock.json` is generated with the supported Node/npm toolchain, reviewed, and committed.
- [ ] `node scripts/check-version.mjs 2.0.12` passes.
- [ ] `mvn clean verify` passes in `backend/`.
- [ ] `npm ci --ignore-scripts && npm run check` passes in `frontend/`.
- [ ] Clean PostgreSQL startup applies Flyway migrations V1–V6 successfully.
- [ ] Packaged backend reports healthy through `/actuator/health`.
- [ ] Administrator, librarian, and member smoke journeys pass.
- [ ] Administrator staff-account create/filter/enable-disable/password-reset flows pass.
- [ ] CSV import/export smoke verification passes with fictional data.
- [ ] Keyboard, zoom, reduced-motion, and screen-reader accessibility review is recorded.
- [ ] Isolated backup/restore drill succeeds.
- [ ] Backend CI, Frontend CI, Version Sync, CodeQL, and relevant security/dependency checks are observed successful.
- [ ] `main` branch protection/ruleset is enabled with stable required checks.

## Release command after all gates pass

```bash
git tag -a v2.0.12 -m "LibraCore v2.0.12"
git push origin v2.0.12
```

The tag push invokes `.github/workflows/release.yml`. The workflow must be the artifact source of truth for the GitHub release.

## Known pre-tag blocker at preparation time

`frontend/package-lock.json` is not yet present on `main`. The source therefore remains a **2.0.12 release candidate**, not a verified published release. Use the **Frontend Lockfile Bootstrap** workflow or a supported local Node/npm environment to generate and review it before tagging.

## Upgrade/database notes

The current database history consists of Flyway migrations V1 through V6. Never edit an already-applied migration to retrofit a release. Review database backup/restore and rollback implications before deployment; application rollback does not automatically reverse database changes.
